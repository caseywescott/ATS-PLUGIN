# Modern ATSH Acceptance Gates

Phase 7 turns the PRD section 7 quality goals into a deterministic acceptance
harness. The harness lives in `src/core/AtsModernAcceptance.h` / `.cpp` and is
covered by a tiered set of CTests.

## Synthetic fixture gates (always deterministic, always run in CI)

`ats_modern_acceptance` runs entirely in-process with synthetic models:

- Classic render parity — normalized RMS error and compact spectral distance.
- Modern tracker vs. classic tracker on crossing/close-partial and sustained fixtures.
- Transient marker/buffer preservation, attack sharpness, and click-step limits.
- Partial plus orphan residual energy preservation.
- Deterministic morph recipe recall and fixed-seed morph renders.
- Modern synthesis real-time-safety flags, finite sample output, and CPU budget.

`ats_modern_acceptance_external_gates` tests the external fixture gate evaluation
logic (Phase 7 addition) using synthetic data — no audio assets needed.

Each gate emits a stable id, observed value, threshold, pass/fail state, and a
short detail string. Callers can keep the default thresholds or supply a stricter
fixture-specific threshold struct.

### Synthetic fixture status

| Fixture | Coverage |
| --- | --- |
| Classic parity sine | normalized RMS and spectral distance stay at zero for identical renders |
| Crossing partials | modern slope-aware assignment has fewer identity errors than classic nearest matching |
| Sustained tone | modern continuity and identity match classic behavior |
| Protected attack | transient marker and buffer increase attack sharpness while staying below the click-step guardrail |
| Morph recall | recipe JSON and fixed-seed rendered output are deterministic |
| Modern synth | render plan reports caller-owned buffers, no allocation/locks/I/O/analysis, finite samples, and bounded CPU |

## External real-audio gates (optional, gated by ATS_ENABLE_EXTERNAL_FIXTURES)

Phase 7 adds a second tier for side-by-side comparison with original ATSA/Qatsh
on curated real audio clips. These run only when configured with
`-DATS_ENABLE_EXTERNAL_FIXTURES=ON` and the assets are present.

### Fixture manifest

`tests/fixtures/ats_external_fixture_manifest.json` — schema version 1.

Each entry declares:

| Field | Purpose |
| --- | --- |
| `id` | Stable fixture identifier used in all check IDs |
| `description` | Human-readable summary |
| `category` | Fixture category (matches Phase 0 categories) |
| `input_audio` | Relative path from `tests/fixtures/` to the WAV file |
| `provenance.license` | License text — must not be PENDING before committing audio |
| `expected_sample_rate` / `expected_channels` | Validated by the driver |
| `enabled_gates` | List of gate names to evaluate |
| `threshold_overrides` | Optional per-fixture overrides for default thresholds |
| `atsa_reference.metadata` | Path to raw `ats_offline --metadata` JSON |
| `atsa_reference.summary_metrics` | Path to stable summary JSON loaded by the C++ gate |

### Gate names

| Name | What is checked |
| --- | --- |
| `classic_parity` | Normalized RMS error and spectral distance vs. ATSA reference |
| `tracker_continuity` | Continuity score regression and identity error increase vs. ATSA |
| `residual_energy_preservation` | Orphan residual ratio delta vs. ATSA reference |
| `transient_preservation` | Attack sharpness ratio vs. ATSA reference |

### Reference artifacts

Reference metrics are generated by `tests/generate_atsa_references.py`. This
script is NOT part of the normal CI flow — run it manually before audio is
committed:

```sh
python3 tests/generate_atsa_references.py \
  --ats-offline ./build/tools/ats_offline \
  --manifest tests/fixtures/ats_external_fixture_manifest.json \
  --output-dir tests/fixtures/reference
```

Output per fixture:
- `tests/fixtures/reference/<id>_atsa_metadata.json` — raw `ats_offline` metadata
- `tests/fixtures/reference/<id>_summary.json` — stable sorted metrics loaded by the gate

### Current external fixture status

All five fixtures (sustained_flute, plucked_guitar, sung_vowel, drum_hit,
crossing_strings) have PENDING license status. Audio files must not be committed
until a redistribution-compatible license is confirmed and added to the manifest.

When assets are missing, the Python CTest skips fixtures cleanly and exits 0
with a message. The gate-logic C++ test always runs and always passes on
synthetic data.

## Design principle

**Synthetic fixtures are the CI baseline.** They catch regressions without any
external assets and run deterministically everywhere.

**External fixtures are the stricter real-audio parity gate.** They catch
divergence from original ATSA behavior on actual recorded material. They are
optional so CI remains fully reproducible without committing audio files.
