# Spectral-Envelope Fixture Manifest

**Status:** Phase 0 planning manifest
**Related docs:** [SPECTRAL_ENVELOPE_PRD.md](./SPECTRAL_ENVELOPE_PRD.md), [SPECTRAL_ENVELOPE_TASKS.md](./SPECTRAL_ENVELOPE_TASKS.md)

This manifest defines the fixture suite needed to validate spectral-envelope transfer for general ATS material. It intentionally includes speech and voice, but does not center the suite on speech or require a stable F0. Synthetic fixtures should be preferred for algorithmic edge cases because they are deterministic, compact, and license-clean.

---

## Fixture Rules

- Every fixture must record provenance, license, sample rate, channel count, duration, and whether it is synthetic or recorded.
- Recorded fixtures must be redistributable under a project-compatible license before they are committed.
- Synthetic fixtures must record the generation recipe, random seed if any, and expected analysis characteristics.
- Tests must not require any fixture to be harmonic, monophonic, voiced, or speech-like unless that fixture explicitly exists for that case.
- Large audio files should stay out of the repo until a fixture-size policy is approved.

## Synthetic Fixture Generation Requirements

Synthetic fixtures should be generated by deterministic scripts under `tests/fixtures` or directly inside Python test helpers until the audio suite is formalized. A generation recipe should include:

- sample rate and duration,
- partial frequencies and amplitudes,
- envelope curve used to create amplitudes,
- residual or noise-band model if present,
- transient time/gain if present,
- random seed for noise.

For Phase 0, the baseline comparison uses synthetic partial frames only. Later phases can promote those recipes into reusable fixture generators.

## Metric Definitions

- **Fit error:** weighted RMS error between fitted log envelope and expected log envelope at fixture points.
- **Smoothness:** derivative or second-derivative energy of the estimated envelope, measured on a fixed frequency grid.
- **Over-oscillation:** local extrema or high-curvature excursions not implied by fixture points.
- **Frame shimmer:** frame-to-frame variation of envelope coefficients or sampled envelope values for sustained fixtures.
- **Transfer discontinuity:** jump in transformed partial amplitudes between adjacent frames.
- **Residual energy preservation:** difference between expected and rendered residual/noise-band energy.
- **Transient sharpness:** spectral flux or attack-window energy ratio before and after transfer.

## Timbre Descriptor Analytical Fixtures

Analytical timbre-descriptor fixtures live in
`tests/fixtures/timbre_descriptor_analytical_fixtures.json` and are materialized
deterministically by `tests/timbre_descriptor_analytical_fixtures.py`. Their
purpose is different from the envelope-fit fixtures above: they exercise
*descriptor correctness* against synthetic inputs whose analytical values are
known. Recorded ATSA references remain regression gates; these are the
correctness gates.

Provenance rules for descriptor analytical fixtures:

- Every fixture has a stable id and a category that appears in
  `tests/fixtures/timbre_descriptor_manifest.json` (`$fixture_categories`).
- Partial amplitudes are linear unless an `amplitude_db` field is provided, in
  which case the builder converts via `10^(db / 20)`.
- Residual bands carry an optional `orphan` flag so the orphan-residual ratio
  has a known target.
- Fitted envelopes are generated from one of `constant_db`, `log_log_line`, or
  `two_raised_cosine_peaks` shapes with documented parameters; the grid is
  always uniform in Hz.
- Waveform spectra use a documented synthetic recipe so cepstral peak
  prominence and high-frequency-content checks have a known floor and harmonic
  layout.
- Series fixtures specify `frame_hop_seconds` and either explicit per-frame
  data, a `generator` block (e.g. AM modulation), or a `tracks` block (per
  track amplitude curve with documented start/end frames).
- Expected analytical values appear under the fixture's `expected` field;
  bounded expectations (low/high bound) are explicit so estimator differences
  do not require the builder to know the implementation.

Tolerances live in the JSON file under `tolerances` so the analytical test
suite (C++ and Python) uses one shared, versioned set.

The Python self-test
(`tests/timbre_descriptor_analytical_fixtures.py`) is registered as
`timbre_descriptor_analytical_fixtures_check` in CTest and verifies that the
builder loads, is deterministic, produces unique ids, and recovers the spot-
check analytical values for the two-partial centroid, the partial/residual
split, and the AM amplitude trajectory.
